Status key: **SAME**; **DS** same semantics, different spelling; **PARTIAL**; **MISSING**;
**DBD** different by design (see RFC-0067); **OOS** out of scope: a Book feature Forbic does not provide because a recorded decision
rules it out (the row names it), or a row on which the Book is silent; **EXT** a Forbic feature
the Book does not have. `[U]` marks what the Book itself calls unreleased, planned or
internal to Epic.

The Book "represents the head of the main development branch" and documents some features
before release
([Epic](https://dev.epicgames.com/documentation/en-us/fortnite/verse-language-book-of-verse-reference)).
It also describes two runtimes, the "Verse VM" and the "BPVM" (Blueprint VM), which differ in
integer width and in the order of class `block` clauses ([02:90](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L90), [10:168](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L168)).

## Corrections to the plan

Written during verification in October 2026 and kept as the record of why the plan changed;
the tables below carry the current status. Most important first. "Plan" is parity-plan.md;
"analysis" is book-compatibility.md.

1. **`defer` does not run on failure (P1.1).** The plan says `Defer` "runs on every exit of
   its block, including failure". The Book: "if a function fails due to speculative
   execution, deferred code does **not** execute", because rollback undoes the scheduling of
   the defer ([07:1206](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L1206)). It runs on normal exit, `return`, `break` and cancellation, in LIFO
   order ([07:1184](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L1184), [07:1235](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L1235), [07:1254](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L1254)), and a defer block cannot fail, suspend, be empty,
   be used as a value, or contain `return`/`break` ([07:1339](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L1339)). One sentence in the
   concurrency chapter says "normal completion, failure, or cancellation" ([14:1120](https://github.com/verselang/book/blob/2af9dfd/docs/14_concurrency.md#L1120)); the
   control chapter is the detailed rule and has a test beside it.
2. **`break`, `return`, `loop` are narrower than the plan assumes (P1.1).** `break` exits only
   the innermost `loop` and "cannot exit `for` loops early" ([07:764](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L764)); it has bottom type
   and carries no value ([07:482](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L482)); there is no `continue` ([07:768](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L768)). `return` must be in
   tail position of its scope ([07:1067](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L1067)) and is rejected in `spawn`, `branch`, `defer` and
   class bodies ([14:595](https://github.com/verselang/book/blob/2af9dfd/docs/14_concurrency.md#L595)). `loop` has type `true` ([07:506](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L506)). The Book has **no `while`**
   (no occurrence in any chapter): `While` (RFC-0060) is a Forbic extension. The name
   `Loop` is already taken in Forbic by the state loop `Loop(Step, Initial)` (RFC-0035), so
   the plan's `Loop{...}` needs a spelling decision.
3. **`case` has no bindings, guards or type tests (P1.6, analysis gap 4).** Scrutinees are
   `int`, `logic`, `char`, `string`, enums and refinement types; "They do not work on
   `float`, objects and tuples" ([07:389](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L389)). Patterns are literal values, enumerators and `_`.
   Type tests in the Book are failable casts in `if`/`else if` chains ([08:565](https://github.com/verselang/book/blob/2af9dfd/docs/08_failure.md#L565)). What the
   Book has and Forbic lacks: a `case` without a default in a `<decides>` context fails on
   no match ([07:440](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L440)); open enums always need `_` or `<decides>` ([07:457](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L457)); unreachable
   arms are errors and a redundant `_` is a warning ([09:421](https://github.com/verselang/book/blob/2af9dfd/docs/09_structs_enums.md#L421)); `@ignore_unreachable`
   ([09:473](https://github.com/verselang/book/blob/2af9dfd/docs/09_structs_enums.md#L473)). P1.6 should be re-scoped to these.
4. **`int` is not simply "unbounded" (P1.3).** "VerseVM uses arbitrary precision"; "BPVM uses
   64-bit integers and raises a runtime error (`MathIntrinsicCallFailure`) on overflow"
   ([02:90](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L90)). Literals must fit 64 bits ([01:52](https://github.com/verselang/book/blob/2af9dfd/docs/01_expressions.md#L52)); wider values cannot be interpolated or
   persisted ([01:56](https://github.com/verselang/book/blob/2af9dfd/docs/01_expressions.md#L56), [17:54](https://github.com/verselang/book/blob/2af9dfd/docs/17_persistable.md#L54)). Forbic's checked `i64` already matches one documented
   runtime; what is missing is the name `int`, not necessarily bignums. `rational` has no
   literal, is produced only by `/`, and the Book documents only `=`, `Floor` and `Ceil` on
   it (both total on a rational) plus `int <: rational` ([02:103](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L103), [02:160](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L160), [02:224](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L224));
   rational arithmetic and ordering are not specified. The plan omits `Quotient` and `Mod`,
   which are Euclidean and failable ([api:172](https://github.com/verselang/book/blob/2af9dfd/verse_api_overrides.md#L172), [api:193](https://github.com/verselang/book/blob/2af9dfd/verse_api_overrides.md#L193)); Forbic's truncating `/` matches
   neither. `set /=` is a compile error on `int` ([04:128](https://github.com/verselang/book/blob/2af9dfd/docs/04_operators.md#L128)).
5. **The effect list is wrong (P1.10).** `<varies>` does not occur anywhere in the Book; only
   Epic's 2025 glossary still lists it. `<converges>` is "only allowed on `<native>`
   functions, abstract methods, and type signatures" ([13:127](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L127), [13:439](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L439)). `<predicts>` is
   "not yet released" ([13:398](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L398)); `no_rollback` has no specifier and is being deprecated
   ([13:389](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L389)). The model is one bit per fundamental effect in six families; an unannotated
   function has `reads`, `writes`, `allocates`, `dictates` and cannot fail or suspend
   ([13:138](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L138), "The `<transacts>` is the default for functions" [13:302](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L302)); a specifier resets
   only its own family ([13:155](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L155)); at most one of the exclusive `<converges>`, `<computes>`,
   `<transacts>` ([13:99](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L99)); `<decides>` and `<suspends>` exclude each other ([13:126](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L126)). The
   analysis line "the Book's effects are additive" has it backwards for the heap family: the
   default is the maximum and a specifier narrows it. Effects are part of function types and
   "a function with fewer effects can be used where a function with more effects is
   expected" ([13:539](https://github.com/verselang/book/blob/2af9dfd/docs/13_effects.md#L539)).
6. **Strings have no ordering (P1.4, analysis gap 2).** `<`, `<=`, `>`, `>=` are defined for
   `int` and `float` only ([04:211](https://github.com/verselang/book/blob/2af9dfd/docs/04_operators.md#L211)); strings support `=` and `<>` ([02:748](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L748)). "String
   ordering" and "ordering is by code point" have no Book counterpart. `string` is an alias
   for `[]char` ([02:602](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L602)), so indexing, `Length`, `Slice`, `+`, `Find`, `ReplaceAll`,
   iteration and element `set` are the array operations; `char` is a UTF-8 code unit and
   `char32` a code point, with no implicit conversion between them or to `int`
   ([02:600](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L600), [01:157](https://github.com/verselang/book/blob/2af9dfd/docs/01_expressions.md#L157), [02:717](https://github.com/verselang/book/blob/2af9dfd/docs/02_primitives.md#L717)).
7. **Maps (P1.5, analysis gap 10).** There is no key removal: "Verse does not have a direct
   'delete' or 'remove' operation for maps" ([05:374](https://github.com/verselang/book/blob/2af9dfd/docs/05_mutability.md#L374)). A duplicate key in a literal keeps
   the last value *and moves the key to the position of its last occurrence* ([03:925](https://github.com/verselang/book/blob/2af9dfd/docs/03_containers.md#L925));
   the analysis only says "keeps the last". Map equality is order-sensitive ([03:906](https://github.com/verselang/book/blob/2af9dfd/docs/03_containers.md#L906)).
   Arrays and maps other than `string` are "not yet implemented" as keys ([03:760](https://github.com/verselang/book/blob/2af9dfd/docs/03_containers.md#L760);
   contradicted at [03:1025](https://github.com/verselang/book/blob/2af9dfd/docs/03_containers.md#L1025)). Lookup accepts a supertype key, `set` does not ([03:963](https://github.com/verselang/book/blob/2af9dfd/docs/03_containers.md#L963)).
8. **`any` has no casts out (P1.7).** The plan says "`any` as a top type with casts out". The
   Book: "Because `any` is not castable, it is a sticky type" ([11:224](https://github.com/verselang/book/blob/2af9dfd/docs/11_types.md#L224)); casts are for
   classes and interfaces only ([11:356](https://github.com/verselang/book/blob/2af9dfd/docs/11_types.md#L356)). Further: maps are covariant in key and value, not
   only arrays, options and tuples ([11:44](https://github.com/verselang/book/blob/2af9dfd/docs/11_types.md#L44)); "Using the same type in multiple constraints
   is not yet supported" ([11:521](https://github.com/verselang/book/blob/2af9dfd/docs/11_types.md#L521)); type arguments of functions are inferred, never written
   ([06:1318](https://github.com/verselang/book/blob/2af9dfd/docs/06_functions.md#L1318)); variance of parametric classes is inferred from use ([10:1306](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L1306)); parametric
   types cannot be `<castable>` or `<persistable>` ([10:2641](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L2641), [09:147](https://github.com/verselang/book/blob/2af9dfd/docs/09_structs_enums.md#L147)); `void` accepts any
   value ([11:1168](https://github.com/verselang/book/blob/2af9dfd/docs/11_types.md#L1168)).
9. **Classes (P1.8).** `<castable>` is not what enables dynamic casts: "All classes and
   interfaces support dynamic casting regardless" ([11:292](https://github.com/verselang/book/blob/2af9dfd/docs/11_types.md#L292)); it is required only for
   `castable_subtype` ([10:2484](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L2484)). Not in the plan: `<final>` on fields and interface
   members ([10:2797](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L2797)), `<final_super_base>` ([10:2927](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L2927)), data-member `<override>`
   ([10:2439](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L2439), [10:3172](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L3172)), `let:` in archetypes ([10:227](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L227)), `super{...}` ([10:381](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L381)),
   qualified member definitions `(c:)F` ([10:956](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L956)), covariant override results ([10:523](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L523)),
   "an overriding method may not widen the effects it inherits" ([10:434](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L434)), failable
   constructor functions ([10:639](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L639)), class-level effects ([10:1817](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L1817)). Three unlisted
   divergences were found: the default access of members is `<internal>` ([10:2091](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L2091),
   [12:151](https://github.com/verselang/book/blob/2af9dfd/docs/12_access.md#L151)) while RFC-0063 makes it public; classes without `<unique>` "cannot be compared
   for equality at all" ([10:2174](https://github.com/verselang/book/blob/2af9dfd/docs/10_classes_interfaces.md#L2174)) while RFC-0063 compares every class by identity; and
   overloads whose parameters are subtype-related classes are rejected ([06:1909](https://github.com/verselang/book/blob/2af9dfd/docs/06_functions.md#L1909)) while
   RFC-0063 picks the most specific.
10. **Iteration (P1.2).** `A..B` is inclusive at both ends, `int` only, empty when `A > B`,
    not a value, and also allowed as the iterated expression of `sync`, `rush` and `race`
    ([07:795](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L795), [07:877](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L877)). `std.range(N)` yields `0..N-1` and is not the same thing. Filters
    "must be failable" ([07:836](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L836)); a filter or binding may precede a generator and a `for`
    may have no generator at all ([07:885](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L885), [07:902](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L902)); strings are iterable ([07:693](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L693)). The
    Book says only that a failing *header* skips the iteration ([07:740](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L740)); it does not say
    what a failing *body* does, so "failable bodies" in the plan and "bodies that fail the
    whole `For`" in RFC-0056 are not Book rules.
11. **Features of the Book with no plan id.** `first` ([07:921](https://github.com/verselang/book/blob/2af9dfd/docs/07_control.md#L921)); `logic{}` and `option{}`

    `(local:)`, `(/path:)` ([16:556](https://github.com/verselang/book/blob/2af9dfd/docs/16_modules.md#L556), [16:687](https://github.com/verselang/book/blob/2af9dfd/docs/16_modules.md#L687)); tuple/argument flattening, tuple-to-array

    ([11:588](https://github.com/verselang/book/blob/2af9dfd/docs/11_types.md#L588)); `subtype`, `concrete_subtype`, `castable_subtype`, `classifiable_subset`
